# Authored activity references

These ten examples were written directly by the coding assistant on 16 September 2026, at the owner's request. They are candidate reference outputs for a later comparison with Lanternina's agents. They were not generated by the production prompts, sent to Foundry, rendered, physically performed or reviewed by an educator. Their quality is an editorial judgement, not an established educational result.

## Working assumptions

The intended participant is an adolescent with moderate intellectual disability. The owner's description of a differentiated secondary-school pathway supplies context, not a complete account of reading, communication, motor skills or independence. These examples make no claim about the legal name or certification of that pathway.

For this set, assume that the adolescent can choose between two clearly different visible options, make a broad mark or point, and attempt one concrete action at a time. A familiar adult can read a short instruction, demonstrate an action on separate material and help position the camera. Independent reading, extended writing, mental arithmetic and explaining a reason in words are not prerequisites. These are assumptions to confirm with the person, not properties of everyone with this diagnosis.

Each example states its additional requirements. A parent prepares the named materials before approving it and remains available for the stated support. Pointing is a valid response for the person; it reaches the system only through an explicitly recorded mark or a parent report. A photograph cannot establish who performed an action or how much assistance they received. If the assumed access method does not work, adapt it before offering the task rather than treating the result as a failure.

## How to read an example

The brief and comparison notes are for adults evaluating the output. Italian passages under `Parent output`, `Script output`, `Display`, `Help` and `Closing output` are authored strings that the corresponding component could produce. The page JSON objects use the current `Page` fields. They are not complete `Experience` documents and do not claim to execute in the current runner.

Every image prompt is written out in full and can be sent independently. It asks for an activity page, not an advertising scene or a photograph of somebody working. The page JSON and the prompt must agree on every printed word. An illustration that supplies a clue or a folding guide is functional content and needs inspection before delivery. Passing a JSON parser does not establish that the image has the right geometry or text.

Returns are invented observations, not an assistant's prediction of what the adolescent will do. The main continuation is conditional on the stated observation. The alternative branches are part of the reference, particularly when a return is incomplete, ambiguous or unrelated. They are not instructions to produce the same response regardless of the evidence.

## Principles behind this set

An activity starts with a visible material and a concrete action. It does not require the adolescent to imagine a situation, remember a long instruction and formulate an explanation before anything can happen. Small choices affect what is actually printed or done next. Familiar materials reduce preparation, but the finished objects and subjects should still suit an adolescent's interests.

Help makes the current action easier to begin. It does not supply a different task or quietly do the reasoning for the person. A parent may help physically, but the system does not infer independence from the resulting photograph. The examples avoid grading, generic praise and claims about learning from one successful action.

There is no required count of exchanges. A useful continuation changes one thing in response to the returned material. A finished activity stays finished. A blank sheet, an unreadable photo and a stop request are different events. A request for clarification can happen once; it does not become a repeated demand to finish.

## Comparison protocol

Give the production workflow only the household assumptions and the chosen example's brief, not the authored answer. Keep these examples outside generation prompts during a held-out comparison. Preserve the full run, actual image prompts, images, observations and continuations. Record assistance explicitly when known; leave it unknown otherwise.

Compare the first plan before showing any return. Then supply the same authored return to both the reference analysis and the production continuer. Use a contrasting return too. If two different choices produce essentially the same next page, the continuation has not used the choice. Inject an unclear photograph separately from a genuinely unchanged page, and supply a stop request independently of either.

For each comparison, record an observed match, an observed defect or an untested point, with the exact text or image region. Check the first actionable instruction, completeness of supplied material, amount of simultaneous reasoning, image fidelity, use of actual evidence, support for an unexpected valid answer, closure and necessary adult effort. Do not collapse these into a single educational score. A shorter or different activity can be better than its reference; this set is not a fixed answer key.

## Workflow boundaries to test

The current page maker sees the page fields, not the parent script. A clue or instruction that exists only in the script is missing from the delivered activity. The examples therefore place required instructions in the page or display output as well.

Photographs of bridges, table arrangements and objects require interpretation of a scene, not merely detection of added ink. Paired-photo comparison requires the earlier observation or image to remain available. Some examples also require a reliably registered stop, completion or parent report. These are explicit requirements of the reference experience, not assertions that every route exists in the current runner. Record any mismatch as a workflow gap rather than changing an observation to make the run pass.

Elapsed human time has not been measured. There is no minimum-duration target for these references. The parent sets an end time, and each example includes a closure for an incomplete path. Image generation and network waiting do not count as useful activity time.

## Local checks

Run the following command from the repository root with the repository Python environment:

```powershell
python officina/authored-examples/check_examples.py
```

The check requires at least ten examples, parses every page through the current `Page` contract and compares every quoted string in its image prompt with the page's printable words. It covers final pages as well as exchanges and rejects page objects outside checked sections. It also checks that the main editorial sections and alternative-return categories are present. It makes no model calls and does not validate image geometry, clinical suitability or whether a person will enjoy an activity.
