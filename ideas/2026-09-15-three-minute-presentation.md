## Annotations

The owner supplied the portable reference now stored in `site/docs/WHITEBOARD.md`. Its navigation guidance was updated on 16 September 2026 after accidental slide changes while writing. `site/src/scripts/whiteboard.ts` adapts it for the presentation only. Each slide has an SVG overlay inside its scrolling area. Pen proximity arms the overlay and disables pen panning; mouse and touch restore ordinary scrolling unless the mouse-drawing checkbox is enabled. The eraser removes whole nearby strokes. Width uses the pressure at the start of a stroke, matching the reference rather than claiming continuously variable brush pressure.

Colours, width, undo and clear belong to a collapsible toolbar inside the top menu. The owner requested this position on 16 September 2026 so the tools would leave the slide unobstructed. Opening the toolbar preserves the menu's height and the slide's dimensions. Colours appear first; the tool strip scrolls horizontally when it cannot fit. At widths of 1100 CSS pixels or less, the wordmark is hidden while the tools are open, leaving the language and menu controls available. This preserves slide space at the cost of scrolling to reach some tools on narrow screens. Browser checks passed in both languages at widths of 1280, 1152, 768, 390 and 320 CSS pixels: opening and closing left the deck's rectangle unchanged, the tools stayed within the header, and colour selection, mouse drawing mode, width adjustment and notes remained accessible. Clear affects only the current slide and asks for confirmation. Undo also restores erased or cleared strokes, with a maximum of 50 action snapshots per slide in memory. Restored strokes can be undone after reloading.

The four-slide backup keeps ink under `lanternina-presentation-ink-v2:it` or `lanternina-presentation-ink-v2:en` in the browser's local storage. The three-slide version saves under `lanternina-presentation-ink-present3:it` or `lanternina-presentation-ink-present3:en`. It reads the existing `v2` annotations until it has its own saved record, matching strokes by their content keys. Its principles slide keeps the original `slide-4` ink key despite becoming slide 3. Saving or clearing annotations in either version leaves the other version's saved record untouched, including the removed paper slide. Previous `v1` entries also remain untouched. Ink is never uploaded. Storage failure leaves drawing available in memory, so persistence depends on browser permissions and available space. Each record contains only recognised colours, a bounded width and finite normalised coordinates. The languages have separate records because translated layouts differ. Coordinates scale with the slide's content area; annotations are not attached to individual words, so a responsive reflow can change their alignment. Use the intended presentation viewport when annotating.

The reordered system and paper slides declare `data-ink-page` with their original `v2` keys. Loading and saving use those keys while navigation uses the current slide numbers. Existing drawings therefore follow their content after the swap; the first and fourth slides retain their original keys.

### Explicit page changes

On 16 September 2026, the owner reported unintended slide changes while writing. The deck's touch handler interpreted horizontal movement of at least 70 CSS pixels as navigation, independently of the annotation engine. Pointer capture and native gesture suppression did not disable that handler. The presentation now uses explicit navigation controls and keyboard commands; the drawing surface has no swipe navigation. This removes the conflict with incidental touch contacts at the cost of changing pages with a separate command. The whiteboard reference records the same integration rule and requires tests that combine pen and touch events, including touch release after a stroke ends.

The browser probe reproduced the defect on the published version: a synthetic touch moved 160 CSS pixels to the left while the pen overlay was armed, changing slide 2 to slide 3. The corrected local build passed the combined pen/touch, eraser, mouse, content-click and wheel checks in Italian and English at 1280 by 720 and 390 by 844 pixels. Previous/next buttons, index links, Arrow Left, Page Down, Home and End still changed slides. Ink was saved under the existing content key and restored only on its own slide. The browser reported no page errors. The build and the 16-page structural check passed. These are synthetic browser checks, not a physical pen-and-palm trial or confirmation that the correction has been published.
