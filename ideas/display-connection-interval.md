# Display connection interval

On 9 September 2026 the owner requested a parent setting for how often e-paper displays connect. Both installed displays were polling about every 65 to 66 seconds because their registry records still had `mains=true` and the mains interval was 60 seconds. The battery default was 600 seconds. These are measured configuration and request-log values, not estimates of battery life.

The Devices page sets `displayPollMinutes` separately for each display, accepting whole minutes from 1 to 1440. Rhythm retains picture-generation cadence. Longer intervals reduce Wi-Fi wakeups but delay new photographs, reminders and other updates. Low-battery protection can lengthen the interval; a button-response cycle temporarily uses the existing short interval.

The panel persists each value in the device inventory and returns effective values in the existing inventory response. The previous household value remains the migration fallback. The hub's status service fetches that response about once a minute, plus discovery and request duration, and atomically writes a device-ID map and the common fallback to `display-poll.json` beside `jobs.json`. Network failure leaves the last saved values intact; old caches remain readable. The display server rereads the cache on every request and selects by authenticated display identity. The existing TRMNL 1.8.12 firmware consumes seconds in `refresh_rate`. No display firmware update, USB connection or reset is needed. A sleeping display receives the new interval only at its next connection and then applies it to subsequent sleep cycles.

The configured minutes describe the requested sleep interval, not an exact wall-clock period: Wi-Fi connection and rendering add time. The hub logs the interval actually sent to each display without logging its token. API tests verify persistence and older-client preservation; a live HTTP-server test changes the cache from 10 to 25 minutes and gets 600 then 1500 seconds on consecutive requests without restarting the server. Low-battery protection and `update_firmware=false` are also checked.
