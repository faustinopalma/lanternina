## What is working and what is unproved

Real USB captures reached the hub and synchronized to the private cloud photo archive. Three earlier verified JPEGs were 113,136, 134,520 and 178,635 bytes at 1600 x 1200. The installed first-frame revision produced 543 ms framebuffer-ready time in two captures versus 831 ms after two warm-up frames. Its final test recorded 1,873 ms for acquisition plus verified storage and 711 ms for upload. These measurements start inside capture: they exclude boot, scheduling and physical debounce, and framebuffer readiness is not the exposure timestamp. The image is fixed before upload; the two delivery flashes happen later.

The public photo panel supports authenticated originals, download, single/all/date-range deletion with previewed IDs, and bounded camera diagnostic history. The hub synchronizes deletion tombstones so retries do not restore deleted images. Live synthetic upload, duplicate, deletion and reupload-after-deletion were tested against the cloud. Infrastructure backup/version retention and user downloads are outside that application deletion path; do not claim complete physical erasure without checking them.

Camera telemetry distinguishes `sleep_planned` from `previousSleepConfirmed`. Only an ESP_RST_DEEPSLEEP reset plus an RTC marker confirms the preceding sleep transition. Battery logs did demonstrate those transitions, but some were followed by immediate unintended button wakes (`sleepSeconds=0` at one-second resolution). This proves sleep entry, not low current, battery life or reliable deliberate capture.

GPIO4 intermittently read LOW with the owner reporting a released shutter. Read-only register checks showed HIGH then LOW with the same IO_MUX 0x1b00: pull-up on, pull-down off, input on, output off. This supports an electrical-input investigation but does not identify the faulty part. The owner's 25 kohm reading was with the circuit connected; a separate similar board measured megaohms. Do not claim this establishes damage. During the last passive 60.5-second observation with USB_TEST_OFF, no capture started and the pin sampled HIGH; the intermittent issue remains unresolved.

The base XIAO has no internal battery ADC connection. Battery voltage is null, not a synthetic percentage. An optional 100k/100k divider and 100nF capacitor to D0/GPIO1 are documented and disabled in firmware until assembled/calibrated. USB presence proves neither a battery nor charging.

## Costly traps already verified

- The old vendor-wide USB display provisioner attempted a 16 MiB e-paper backup on this 8 MiB camera. Its service now passes `--registered-only`. Preserve the safeguard and the explicit display enrollment command.
- LittleFS runtime declared a 64-character filename limit, but the actual generated filesystem refused a 37-character path (errno 91); a 16-character test wrote successfully. Use short local basenames (24 hex characters plus suffix), retain the complete 32-character identifier in metadata/receipts, and check collisions. No format was needed to fix it.
- Metadata must be closed before unlink after acknowledgement. Unlinking an open File failed and left an orphan JSON; the corrected code preserves the JPEG if receipt cleanup fails.
- Arduino 2.0.17's TLS verifier rejected an IP SAN alone for the numeric URL. The pinned certificate now includes DNS:lanternina.local, DNS:192.168.0.158 and IP:192.168.0.158. Certificate verification stays enabled. Rotating the certificate requires updating every camera that pins it; adding a camera must not casually renew it.
- A sleeping camera does not wake just because a cable is inserted. The agreed sequence is connect USB, press and release the shutter once, then stay awake on the active USB host. A charger without USB data cannot be identified by bus-frame activity. An external VBUS circuit would be a separate hardware change.
- E-paper defaults had mains=true on both units. On 9 September these were set false and the common cache set to 10 minutes. Real requests at 15:15:37 and 15:16:07 received 3600 and 21600 seconds because the cells were low/critical (latest earlier voltages 3.61 and 3.52 V). Do not treat their silence as a failed deploy. Parent interval changes reach a sleeping display on its next request, not immediately.
- No host-side model inference is used. The hub's image processing and BMP rendering are deterministic utilities. E-paper BMP palette reserved bytes must remain zero; reuse the existing encoder.
- Python tests use `.venv/Scripts/python.exe` on Windows. Terminal PATH's Python lacked pytest; hub uses system Python plus installed Pillow/OpenCV and the existing PlatformIO venv for serial tooling. Avoid installing the whole cloud dependency tree on the hub.
- PowerShell commands are one line with a Stopwatch. Avoid binary shell pipelines and CRLF injection over SSH. `gh run watch ... | Out-String` returned usable final output where a bare watch repeatedly opened an alternate buffer. Do not print credentials in env files, build headers or tokens.
